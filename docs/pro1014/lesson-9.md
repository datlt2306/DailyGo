# Buổi 9 – Review 1 (Giữa kỳ)

## 🎯 Mục tiêu học tập

- Đánh giá tổng thể tiến độ và chất lượng code
- Nhận được feedback từ giảng viên để cải thiện
- Chấm điểm tạm (30% điểm tạm)
- Xác định hướng phát triển cho tuần 4–6

---

## 📋 Nội dung chính trên lớp

### 1. Demo module từng nhóm (60 phút)

#### **Quy trình demo:**
1. Nhóm trình bày module đã làm (7 phút/nhóm)
2. Demo code chạy được (nếu có)
3. Giảng viên phản biện và chấm điểm (3 phút/nhóm)

#### **Nội dung trình bày:**

**1. Giới thiệu module (1 phút)**
- Tên module
- Chức năng chính

**2. Demo chức năng (4 phút)**
- Demo các chức năng đã làm
- Show code hoặc screenshot
- Giải thích cách hoạt động

**3. Tiến độ và kế hoạch (2 phút)**
- % hoàn thành hiện tại
- Các chức năng đã làm
- Kế hoạch tuần tới

### 2. Tiêu chí chấm điểm (10 phút)

Giảng viên giải thích cách chấm điểm:

#### **Điểm tạm: 30% tổng điểm**

**Phân bổ:**
- **Code đã làm** (15%): Module có chạy được không? Code quality?
- **Tiến độ** (10%): Hoàn thành đúng kế hoạch? Commit đủ chưa?
- **Teamwork** (5%): GitHub activity? Phân công công việc?

#### **Thang điểm:**
- **Xuất sắc (9–10)**: Module chạy tốt, code sạch, tiến độ đúng kế hoạch
- **Tốt (7–8)**: Module chạy được, code ổn, tiến độ gần đúng
- **Khá (5–6)**: Module chạy cơ bản, code có vấn đề, tiến độ chậm
- **Yếu (<5)**: Module chưa chạy hoặc chạy lỗi, tiến độ chậm nhiều

### 3. Feedback và góp ý (15 phút)
- Giảng viên đưa ra feedback cho từng nhóm
- Gợi ý cải thiện cho tuần 4–6
- Nhắc nhở các vấn đề cần xử lý

### 4. Tổng kết và định hướng (5 phút)
- Tổng kết chung về tiến độ
- Nhắc nhở deadline tuần 4–6
- Động viên các nhóm tiếp tục phát triển

---

## 🧠 Kiến thức trọng tâm / Giải thích

### Code quality - Tiêu chí đánh giá

1. **Code chạy được**: Không có lỗi syntax, có thể test được
2. **Code sạch**: Có comment, tên biến rõ ràng, format đúng
3. **Cấu trúc hợp lý**: Folder, file được tổ chức logic
4. **Bảo mật cơ bản**: Không có SQL injection, XSS rõ ràng

### Tiến độ - Đánh giá

**Tiến độ tốt:**
- ✅ Hoàn thành ≥70% kế hoạch
- ✅ Có ≥10 commit từ đầu tuần 3
- ✅ Có code chạy được

**Tiến độ chậm:**
- ⚠️ Hoàn thành <50% kế hoạch
- ⚠️ Ít commit (<5 commit)
- ⚠️ Chưa có code chạy được

### Teamwork - Đánh giá

1. **GitHub activity**: Tất cả thành viên đều có commit
2. **Phân công công việc**: Mỗi người đều có việc làm
3. **Communication**: Có trao đổi, báo cáo tiến độ

---

## 📘 Bài tập nhóm

### Nộp link demo + repo + bảng tiến độ

#### **Yêu cầu:**

1. **Link repo GitHub**
   - Repo public, dễ truy cập
   - Có README.md cập nhật
   - Có file PROGRESS.md hoặc bảng tiến độ

2. **Link demo hoặc video demo** (nếu có)
   - Link website chạy (nếu deploy được)
   - Hoặc video demo chức năng (≤5 phút)
   - Hoặc screenshot các màn hình

3. **Bảng tiến độ cập nhật**
   - File Excel hoặc Google Sheets
   - Cập nhật Status của tất cả task
   - Ghi chú % hoàn thành tổng thể

4. **Slide trình bày** (tùy chọn)
   - Tối đa 5 slide
   - Nội dung: Giới thiệu module, Demo chức năng, Tiến độ

### Format nộp

Tạo file `SUBMISSION.md` trong repo GitHub:

```markdown
# Submission - Review Giữa kỳ

## Thông tin nhóm
- Tên nhóm: [Tên nhóm]
- Module: [Tên module]

## Link
- Repo GitHub: [Link]
- Demo/Video: [Link hoặc "Chưa có"]
- Bảng tiến độ: [Link hoặc file đính kèm]

## Tiến độ
- % Hoàn thành: [X]%
- Số commit: [X]
- Chức năng đã làm: [Liệt kê]

## Vấn đề gặp phải
- [Mô tả vấn đề 1]
- [Mô tả vấn đề 2]

## Kế hoạch tuần tới
- [Task 1]
- [Task 2]
```

### Deadline
Nộp trước buổi 9 (gửi link repo hoặc file SUBMISSION.md)

## 💬 Gợi ý giảng viên

### ⏱ Thời lượng gợi ý
- Demo từng nhóm: 60 phút (7 phút/nhóm × 8–9 nhóm)
- Tiêu chí chấm điểm: 10 phút
- Feedback: 15 phút
- Tổng kết: 5 phút
- Tổng: ~90 phút

### 💡 Tips hướng dẫn
1. **Chuẩn bị checklist chấm điểm**: Để chấm điểm nhanh và công bằng
2. **Ghi nhận feedback rõ ràng**: Yêu cầu các nhóm ghi chú feedback để cải thiện
3. **Động viên các nhóm**: Dù tiến độ chậm cũng cần động viên để tiếp tục
4. **Nhắc nhở deadline**: Tuần 4–6 còn nhiều việc, cần tập trung

### 🔍 Câu hỏi thường gặp
- **Q: "Nhóm em điểm thấp, có thể cải thiện không?"**
  - A: Có thể, điểm này chỉ là tạm. Tuần 4–6 vẫn có thể cải thiện và lấy lại điểm.

- **Q: "Nếu module chưa chạy được, điểm sẽ bị trừ nhiều không?"**
  - A: Có, nhưng nếu có code và tiến độ tốt, vẫn có điểm phần tiến độ và teamwork.

- **Q: "Nhóm em có thể thay đổi chức năng không?"**
  - A: Có thể, nhưng cần thông báo với giảng viên và đảm bảo hoàn thành đúng deadline.

# Buổi 8 – Theo dõi tiến độ lần 1

> **Bài trước:** [Buổi 7: Lập kế hoạch triển khai](./lesson-7.md)  
> **Bài tiếp theo:** [Buổi 9: Review 1 (Giữa kỳ)](./lesson-9.md)

## 🎯 Mục tiêu học tập

- Đánh giá tiến độ thực tế so với kế hoạch
- Phát hiện vấn đề và rủi ro sớm
- Điều chỉnh kế hoạch nếu cần
- Đảm bảo tất cả thành viên đều có việc làm

---

## 📋 Nội dung chính trên lớp

### 1. Demo tiến độ từng nhóm (50 phút)

#### **Quy trình demo:**
1. Mỗi nhóm trình bày tiến độ (5 phút/nhóm)
2. Demo code đã làm (nếu có)
3. Giảng viên hỏi và góp ý (2 phút/nhóm)

#### **Nội dung trình bày:**
- ✅ Đã hoàn thành task nào? (% hoàn thành)
- ✅ Đang làm task nào?
- ✅ Gặp khó khăn gì? Cần hỗ trợ gì?
- ✅ Code đã commit lên GitHub chưa?

#### **Minh chứng tiến độ:**
- Link repo GitHub với commit mới
- Screenshot hoặc demo code chạy được
- Bảng cập nhật Status task

### 2. Giảng viên kiểm tra repo GitHub (20 phút)

#### **Các điểm kiểm tra:**
- ✅ Có commit mới không? (≥3 commit từ buổi 7)
- ✅ Commit message có đúng format không?
- ✅ Cấu trúc code có hợp lý không?
- ✅ Có comment code không?

#### **Các vấn đề thường gặp:**
- ❌ Không có commit nào (chưa bắt đầu code)
- ❌ Commit message không rõ ràng
- ❌ Code không có comment
- ❌ Cấu trúc thư mục lộn xộn

### 3. Điều chỉnh kế hoạch (nếu cần) (10 phút)
- Nếu task bị trễ, cần điều chỉnh timeline
- Nếu task quá khó, cần hỗ trợ thêm
- Phân công lại công việc nếu cần

### 4. Thảo luận và giải đáp thắc mắc (10 phút)
- Các nhóm hỏi về khó khăn gặp phải
- Giảng viên hướng dẫn giải quyết

---

## 🧠 Kiến thức trọng tâm / Giải thích

### Cách đánh giá tiến độ

**Công thức:**
```
% Hoàn thành = (Số task hoàn thành / Tổng số task) × 100
```

**Hoặc:**
```
% Hoàn thành = (Số giờ đã làm / Tổng số giờ ước lượng) × 100
```

### Dấu hiệu nhận biết tiến độ chậm

- ⚠️ Ít hoặc không có commit mới
- ⚠️ Nhiều task vẫn ở trạng thái "Chưa bắt đầu"
- ⚠️ Thành viên không biết đang làm gì
- ⚠️ Không có code chạy được

### Cách khắc phục tiến độ chậm

1. **Xác định nguyên nhân**: Task quá khó? Thiếu tài liệu? Thành viên chưa làm?
2. **Điều chỉnh kế hoạch**: Chia nhỏ task hơn, gia hạn deadline
3. **Phân công lại**: Giao task cho người khác phù hợp hơn
4. **Hỗ trợ thêm**: Giảng viên hoặc TA hỗ trợ

---

## 📘 Bài tập nhóm

### Cập nhật tiến độ (≥3 commit mới)

#### **Yêu cầu:**

1. **Cập nhật bảng phân công:**
   - Cập nhật Status của các task
   - Ghi chú % hoàn thành
   - Ghi chú khó khăn gặp phải

2. **Commit code lên GitHub:**
   - Ít nhất **3 commit mới** từ buổi 7
   - Commit message đúng format (feat:, fix:, docs:, v.v.)
   - Code có comment

3. **Tạo file PROGRESS.md trong repo:**
   ```markdown
   # Tiến độ tuần 3 - Buổi 8

   ## Tổng quan
   - % Hoàn thành: [X]%
   - Số task hoàn thành: [X]/[Tổng số]
   - Commit tuần này: [X] commits

   ## Task đã hoàn thành
   - [ ] Task 1: [Tên task] - Assignee: [Tên]
   - [ ] Task 2: [Tên task] - Assignee: [Tên]

   ## Task đang làm
   - [ ] Task 3: [Tên task] - Assignee: [Tên] - % hoàn thành: [X]%

   ## Khó khăn gặp phải
   - [Mô tả khó khăn 1]
   - [Mô tả khó khăn 2]

   ## Kế hoạch tuần tới
   - [ ] Task 4: [Tên task]
   - [ ] Task 5: [Tên task]
   ```

4. **Screenshot hoặc link demo** (nếu có code chạy được)

### Deadline
Nộp trước buổi 9 (cập nhật trong repo GitHub)

---

## 📦 Kết quả mong đợi sau buổi học

- ✅ Đánh giá được tiến độ thực tế
- ✅ Có ít nhất 3 commit mới trên GitHub
- ✅ Xác định được khó khăn và cách giải quyết
- ✅ Điều chỉnh kế hoạch nếu cần

---

## 💬 Gợi ý giảng viên

### ⏱ Thời lượng gợi ý
- Demo tiến độ: 50 phút (5 phút/nhóm × 10 nhóm)
- Kiểm tra repo: 20 phút
- Điều chỉnh kế hoạch: 10 phút
- Thảo luận: 10 phút
- Tổng: ~90 phút

### 💡 Tips hướng dẫn
1. **Tạo checklist tiến độ**: Chuẩn bị checklist để đánh giá nhanh
2. **Khuyến khích commit thường xuyên**: Commit nhỏ, thường xuyên tốt hơn commit lớn
3. **Nhắc nhở về code quality**: Không chỉ commit code chạy được, mà cần code sạch, có comment
4. **Hỗ trợ nhóm yếu**: Nếu nhóm chậm, cần hỗ trợ ngay để không ảnh hưởng tiến độ

### 🔍 Câu hỏi thường gặp
- **Q: "Nhóm em chưa code được gì, phải làm sao?"**
  - A: Cần bắt đầu ngay. Có thể bắt đầu với task đơn giản như setup database hoặc tạo giao diện cơ bản.

- **Q: "Em gặp lỗi mà không biết sửa, phải làm sao?"**
  - A: Hỏi giảng viên, TA, hoặc các bạn trong nhóm. Có thể tạo issue trên GitHub để theo dõi.

- **Q: "Commit bao nhiêu lần là đủ?"**
  - A: Không có số lượng cụ thể, nhưng nên commit sau mỗi tính năng nhỏ hoàn thành (ít nhất 3 lần/tuần).

### 📝 Checklist đánh giá tiến độ

Giảng viên có thể dùng checklist này:

- [ ] Có ≥3 commit mới từ buổi 7
- [ ] Commit message đúng format
- [ ] Code có comment
- [ ] Có file PROGRESS.md hoặc cập nhật bảng phân công
- [ ] Có code chạy được (hoặc ít nhất có cấu trúc code)
- [ ] Các thành viên đều có task được giao
